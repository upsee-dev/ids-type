# iOS 1.0.13（build 22）: iOS 27で起動直後に落ちる問題の修正

最新確認: **2026-11-05 22:02 JST**。

- **iOS 1.0.13（build 22）: App Reviewへ提出済み、`WAITING_FOR_REVIEW`。承認後自動公開（`AFTER_APPROVAL`）。**
- 公開中の1.0.12（build 21）は、iOS 27の端末で起動直後に落ちる。1.0.13の公開で解消する。
- Androidは影響なし。今回の提出もない。

## 症状と原因

- 報告: iPhone 15 Pro / iOS 27.2で、アプリを開くとすぐに終了する。
- 再現: 1.0.12と同じコードのReleaseビルドを、iOS 27.1シミュレーターで起動すると毎回落ちる。
- クラッシュレポート: メインスレッドの`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`で`EXC_BREAKPOINT`。
- iOS 27 SDKでビルドしたアプリは、UIScene のライフサイクルを採用していないと、iOS 27では起動した瞬間にUIKitが止める。1.0.12はiOS 27.1 SDK（Xcode 27.1）でビルドしていた。
- Expo SDK 57 のテンプレートの`AppDelegate`は、`didFinishLaunching`で窓を作る旧方式のまま。

## 修正

- コミット: `d0f1d5d`（`feat/system-ime-and-full-cjk-coverage`、originへプッシュ済み）。
- `native/plugins/withSceneLifecycle.js`を追加し、`app.json`へ登録した。prebuildのたびに次を行う。
  - Info.plistに`UIApplicationSceneManifest`を足す。
  - 窓づくりとReact Nativeの起動を`SceneDelegate`へ移す。
- 起動のきっかけのURL（キーボードの「カメラ」の`ids-kanji-type://camera`）は、`launchOptions`経由で`Linking.getInitialURL`へ渡す。
- 起動後のURLとライフサイクルは、`AppDelegate`（Expoの購読者）へ回す。
- Expoのテンプレートが変わって差し替え箇所が見つからないときは、prebuildを失敗させる。
- 1.0.12は承認・公開済みで同じ版を再提出できないため、版を`1.0.13`、buildを`22`に上げた。Androidの`versionCode 20`は据え置き。
- 提出物には、この修正だけを入れた。同時期の拼音入力・や行フリックの変更（`7778505`）は含めていない。

## 確認

- 修正前: iOS 27.1シミュレーターで起動直後に落ちる（上記クラッシュレポート）。
- 修正後: 同じシミュレーターで起動し、メイン画面が表示され、プロセスが継続することを確認。クラッシュレポートは出ていない。
- 1.0.13のIPA:
  - version 1.0.13 / build 22、SDK `iphoneos27.2`、`app.SceneDelegate`を含む。
  - アプリ・`keyboard`・`japanese`の3つとも`codesign --verify --deep --strict`が成功。
  - 3つともApp Store配布プロファイルで署名され、`group.com.upsee.idskanjitype`を持つ。`get-task-allow=false`。
  - 日本語拡張の辞書は87ファイル（1.0.12と同数）。
- Apple公式`altool`の検証は`VERIFY SUCCEEDED with no errors`。アップロードも成功し、ビルド処理は`VALID`になった。

  - キーボードの「カメラ」からアプリを開く動作。シミュレーターでは「開きますか？」の確認を押せず、試せなかった。

## ビルド手順のメモ

- リポジトリのパスに日本語があるとpod installが失敗する。そのため`git archive d0f1d5d`をASCIIのパスへ展開してビルドした。
- `ExpoModulesJSI`のビルドフェーズは、Xcodeが見るパスの綴り（`/tmp/...`。`/private/tmp/...`ではない）で事前にキャッシュを作ると通る。綴りが違うとハッシュが一致せず再ビルドに入り、Xcode 27の中で失敗する。
