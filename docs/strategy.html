カタチ入力（プロダクト名仮称）
読めない漢字を、見たまま打てる。

漢字の見た目の構造（左右・上下・かこみ＝IDS空間関係）と部品の組み合わせで、読みがわからない漢字をその場で入力できる、日本初の「形」から引く日本語キーボード／IME。

入力方式は zi.tools の IDS 部品入力方式を日本語市場向けに再設計したもの。

LR 日 月 → 明　／　OC 囗 玉 → 国　／　RU 辶 刀 → 辺

位置コード17種（LR=左右, UD=上下, OC=全かこみ…）＋部品 → 候補漢字。読み・画数・部首の知識は一切不要。

エグゼクティブサマリー

  1. 市場の空白：日本語入力は音系（ローマ字・かな・フリック）が事実上100%。中華圏に存在する「形」からの入力（五筆・倉頡）に相当する手段が、日本語市場には存在しない。
  2. 残された課題：読めない漢字（人名・地名・古典・異体字・専門文献）は現状、手書き認識・部首索引・画像検索で迂回するしかなく、遅い／不確実／PCではとくに不便。
  3. 解決策：空間関係コード17個だけを覚えれば、部品は「見たまま」。五筆（字根130〜234暗記）・倉頡（24字母＋取码規則）と異なり学習コストが极めて低い形系入力を実現。
  4. 戦い方：既存IMEの置き換えではなく「2枚目のキーボード」として共存し、置き換え摩擦をゼロに。文字業務のプロ（行政・出版・研究・翻訳）から深く獲得しB2Bへ展開。
  5. 現状：Webプロトタイプ完成（13,108字・応答10ms以下）。次フェーズはスマホIME（iOS/Android）→PC IME。

1. 課題 — 「読めない漢字」は今も入力できない

現代の日本語IME（Google日本語入力・ATOK・Simeji等）は「読める漢字を速く打つ」ことに最適化された音系入力であり、読みがわからない字の前では無力になる。競合調査（CJK入力方式リサーチ）が示す通り、CJK入力は「音码（発音）／形码（字形）／音形混合」に大別されるが、日本市場は音系一色であり、形码系の実用手段が存在しない。

読めない漢字に遭遇するシーン

  • 人名・地名：戸籍・窓口業務、宛名、名刺、旧字体（濵・髙・﨑・栁 等）
  • 古典・漢文・歴史資料：研究・翻刻・くずし字翻刻後の確定入力
  • 専門文献・仏教・医学・法律用語、出版・校正での異体字の同定と入力
  • 学習者：非漢字圏の日本語学習者は「読みを知らない字」が日常（読みを知らないと打てない構造的矛盾）

本質的な空白：「字の見た目はわかっているのに入力できない」という状況に対し、見た目の情報をそのまま受け取る入力チャネルが日本語には存在しない。中華圏では五筆・倉頡が形码としてこの役割を担うが、字根暗記の学習コストが高く専門職に残存する形で定着した（調査レポートの通り）。「低学習コストの形码」はCJK全体でも空白地帯であり、IDS（Unicode標準の漢字構造記述）の空間関係はその解になり得る。

なぜ今か

  • IDS分解データ（CHISE / CJKVI / BabelStone）が成熟し、9万字規模の構造データベースが利用可能になった
  • Unicode 15.1でIDC操作子が17種に拡張され、zi.toolsが「空間関係コード入力」のUXパターンを実証済み
  • インバウンド・国際化で非漢字圏の日本語学習者が増加し、「読めないが見えている字」を打つ需要が拡大

2. ソリューションと USP・競合優位性

入力方式（プロトタイプ実装済み）

  • 位置コード17種＋部品を並べるだけ。部分入力・ワイルドカード（LR氵?）・部品のみ検索（日月→明・盟・朝…）に対応
  • 打ちにくい部品はパレットから1タップ（氵扌艹辶宀疒…46種）。構造の揺れ・字形バリアント（⺼=月）・偏旁の同一視（扌≈手）をエンジン側で吸収
  • 候補は学年・使用頻度順。選んだ字は読み（音訓）・分解を表示 — 「打てた上で、読みもわかる」

USP（一言）

「読めない漢字を、見たまま打てる」— 覚えるのは位置コード17個だけ。

持続的な競合優位（moat）

① 日本語最適化データ

日本字体優先のIDS選択・常用/人名用の網羅・学年/頻度ランキング・偏旁同一視辞書は、使うほど磨かれる独自データ資産。

② IME統合のUX

「調べる」でなく「打つ」。辞書サイトやOCRと違いカーソル位置に直接挿入。この体験差は構造的で模倣されにくい。

③ ニッチ深耕の先行者利益

大手IMEには小さすぎる市場で参入誘因が薄い。専門職コミュニティでの標準化が参入障壁になる。

調査レポートとの整合：形码はCJK全域で「低重码率だが高学習コスト」ゆえ専門職に残存した（五筆・倉頡）。カタチ入力は盲打・速度を捨て「発見可能性」に全振りして学習コスト問題を回避し、速度競争（音系＋予測）には参入せず音系IMEの補完と位置づける — 調査の推奨「既定は音系＋上級モードとして形系」と同型の構成。

提供価値（Jobs to be Done）

機能価値

「目の前の読めない字を、いま書いている文章に、確実に・その場で入れたい」— 部首索引の数分 → 15秒以内へ。

信頼価値

主要リスクと対応

リスク対応
カメラOCR・マルチモーダルAIが「読めない字」を解決してしまう撮れない場面（画面上の字・手書き原稿・崩し字・低品質印刷）と「入力その場完結」に集中。OCR併用機能はむしろ取り込む（撮影→部品確認→確定入力）

反証条件（ピボット判断）

  • 専門職ユーザーテスト（n≥10）で検索成功率が70%を下回り、データ・エンジン改善でも改善しない場合 → 手書き・OCRハイブリッドへ軸足を移す
  • 「読めない字」遭遇頻度が想定より低く、専門職でも週1未満なら → IME単体でなく辞書・校正ツールへの機能提供（SDK/API）モデルに転換
