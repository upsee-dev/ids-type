# 4文字以上の訓読みの完全一致を先頭にする

2026-10-29。アプリ内の読み検索・日本語拡張フリック、既存/追加のiOS・Android入力方式に実装。

- 入力をNFC・ひらがなへ正規化し、4文字以上の訓読み・熟字訓が完全一致する候補を先頭の段にまとめる。小書きかなも1文字として数える。
- `こころざ.す` は `こころざす` と比較する。送り仮名を省いた途中一致、3文字以下、音読み、人名読み、外国語の転写だけではこの優先を付けない。
- 単漢字の参考読みは、日本語の出典を持ち、読みトークン全体がひらがなで一致する場合だけ対象。`悪` の参考読み `いずくにかいずくんぞ` に含まれる `いずくんぞ` は完全一致にしない。
- 完全一致の段内と残りの段内は既存の分類優先順位・コスト・文字順を維持。30画以上はそれぞれの段の中で画数順。ページ分割・表記の重複除去より前に優先を決める。

日本語フリックのTSVは既存の4/6列を維持。分類ビット0–14は変更せず、`1 << 24` を訓読み属性に予約。KANJIDIC2の`ja_kun`の完全な読みと表記の組、ひらがなの日本語参考読みの既存の組に属性を付け、既存の熟字訓・義訓ビット6も優先対象にする。候補・分類数は増減させず、1,631,260組と外国語76,825組を維持する。訓読みの語幹だけに、この属性を流用しない。
