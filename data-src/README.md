# data-src — 辞書の元データ

`core/kanji-data.json` を作るための入力。ここのファイルは**加工しない**（上流のまま置く）。
加工はすべて `web/scripts/build-data.mts` 側でやる。

```
data-src/
├── sources.json        # 出典・URL・版・ライセンス（fetch.mjs が読む）
├── fetch.mjs           # 上の定義どおりに取り直す
├── ids/                # 分解データ（IDS）。1ソース1ファイル
│   ├── babelstone.txt      土台。Unicode 16.0 の全97,680字
│   ├── chise.txt           穴埋め。拡張Jの唯一の供給源
│   └── cjkvi.txt           KANJIDIC2収録字の日本字体
├── kanjidic2/
│   ├── kanjidic2.xml.gz    読み・学年・頻度
│   └── kanjidic2.xml       展開済み（15MB・.gitignore 済み）
├── unihan/
│   └── Unihan.zip          KANJIDIC2 に無い字の読み・画数・IRG の源の記号（18.0.0）
├── irg/                    IRG ワーキングセットの審査ツールから取った表（web で npm run fetch:irg）
│   └── ws2015.jsonl …      字ごとのページの表をそのまま1行1ページで
└── readings/               読みを足す表（国字ほか）
    ├── waseikanji.html     『和製漢字の辞典2014』172ページを連結
    ├── jk.tsv              JK（IRG国字コレクション）の読み
    ├── zi-onyomi.tsv       zi.tools の音読み
    ├── manual.tsv          手で足した読み（どの資料にも無いが、足してほしいと言われたもの）
    ├── zi-variant.tsv      使っていない（推定用だった）
    └── taiwan-min.tsv      使っていない（推定用だった）
```

## Unihan は zip のまま置いている

上流（Unicode）が zip でしか配っておらず、展開すると 25MB ある。ここは
「上流のまま置く」決まりなので zip のまま置き、ビルドのときに必要な2ファイル
（`Unihan_Readings.txt` / `Unihan_IRGSources.txt`）だけを
`web/scripts/build-data/unzip.mts` が取り出す（依存なしの zip 読み）。

版は **18.0.0**（2026-07-31）。17.0 から `kJapanese` が28字ぶん直っている
（仙 に「せんにん」が増えた、など）。

使いどころは**読みの補完**。KANJIDIC2 が読みを持つのは 13,108字だけなので、
`kJapanese`（かな書きの日本語読み・51,583字）で埋める。もう1つは
**IRG の源の記号**（`kIRG_GSource` ほか）で、IRG ワーキングセットの読みを
符号位置に結びつけるのに使う。
詳しくはリポジトリ直下 README の「読み（正式・人名・参考・外国語の4段階）」。

## readings/ は「読みが足りない字」を埋めるためのもの

Unihan の `kJapanese` は51,583字ぶんあるが、**国字（和製漢字）はここに無いことが多い**。
国字は中国の字音を持たないので部品から音を推すこともできず、放っておくと読みで一生引けない。

| ファイル | 何が入っているか | 使われ方 |
|---|---|---|
| `waseikanji.html` | 『和製漢字の辞典2014』（大原望）3,316項目・読みのある字1,631字 | 参考の読み（和製漢字） |
| `jk.tsv` | JK（IRG国字コレクション）の読み | 参考の読み。和製漢字の辞典と重ならない7字が埋まる |
| `zi-onyomi.tsv` | zi.tools の音読み50,144字（呉音・漢音・唐音つき） | 参考の読み。Unihan に無い読みが1,230字ぶんあり、45字がこれだけを出所にする |
| `manual.tsv` | 手で足した読み（いまは 𳍹 いっさき の1件） | 参考の読み（追加） |
| `zi-variant.tsv` | 異体字グループに付く読み24字 | **使っていない**。異体字から借りる推定用だった |
| `taiwan-min.tsv` | 台湾（新北）の閩南語音966字 | **使っていない**。ローマ字として読む推定用だった |

`zi-variant.tsv`・`taiwan-min.tsv` は 2026-09-29 に**推定をやめた**ときにビルドから外した。
取り直しに数時間かかる（相手側が遅い）ので、ファイルだけ残してある。要らなければ消してよい。

どれも**消せば元に戻る**（その字の読みが無くなるだけでビルドは通る）。
再配布条件が明示されていない資料なので、配布形態によっては外す判断があり得る。

## irg/ は外国語の読み

IRG（漢字の符号化を審査する国際会議）のワーキングセット WS2015・WS2017・WS2021・WS2024 の
審査ツール（`https://hc.jsecs.org/irg/<ws>/app/`）から、字ごとのページの表をそのまま取ったもの。
提案した国・地域が、その字の読みを自分の言語で書き添えている（中国語の拼音・壮語・
韓国語・ベトナム語）。**日本語の読みではない**ので、日本語の読みが1つも無い字にだけ、
カタカナに書き写して入れる（`web/scripts/build-data/irg.mts`・`transcribe.mts`）。

```bash
cd web && npm run fetch:irg     # 約2万ページ。2本並行・400ms 間隔で2時間ほど。途中で止めても続きから
```

異体字セレクタ（Itai-ji-selection）にも同じスクリプトがあり、取れるものは同じなので、
片方で取った `irg/` を複製して使ってよい。

## 上流がまだ持っていない字

Unicode の追加に上流の表が追いつくまでは、ここに元データが無い字が出る。
いまは `𫠞`（U+2B81E・Unicode 18.0 で拡張Dの末尾に増えた1字）が該当し、
分解 ⿰日欠 と画数8だけ `web/scripts/build-data/supplement.mts` に手で書いてある
（画数は Unihan 18.0 に入ったのでそちらが使われる）。
上流のほうが優先されるので、BabelStone か CHISE がこの字を載せたら消してよい。

## 取り直す

```bash
node data-src/fetch.mjs           # 無いものだけ
node data-src/fetch.mjs --force   # 全部
cd web && npm run build:data      # 辞書を作り直す
```

## 3つのIDS表を重ねている理由

1字につき1つの分解を選ぶ。優先順位は `web/scripts/build-data/merge.mts` にある。

| | 役割 | なぜ必要か |
|---|---|---|
| **BabelStone** | 土台 | 全97,680字を1ファイルで持ち、字源タグ(G/H/T/**J**/K/P/V)で日本字体を選べる |
| **CHISE** | 穴埋め | BabelStone は Unicode 16.0 準拠で**拡張J 4,298字を1字も持たない**。加えて拡張C/Eの末尾18字など、他の表に分解が無い20字も埋まる |
| **CJKVI** | KANJIDIC2収録字 | 従来の検索結果を変えないため、日本の漢字だけこの表の `[J]` を最優先する |

BabelStone は帰属不要・CHISE と CJKVI は GPLv2。GPLを避けたい配布形態では
`IDS_SOURCE=babelstone` でビルドすると BabelStone だけになる
（そのぶん拡張Jの分解が落ち、4,298字が構造検索に出なくなる）。

### なぜ CHISE だけ連結して置いているのか

CHISE の上流はブロックごとに18ファイルに分かれている。ここでは**「1ソース1ファイル」に
揃えたい**ので、`fetch.mjs` が全部つないで `chise.txt` 1本にして保存している
（各ファイル先頭の `;;` ヘッダも残るので由来は追える）。ブロック別に分けたままだと
BabelStone/CJKVI が1ファイルなのと不揃いになり、「なぜ拡張G〜Jだけ在るのか」が
分からなくなる。

ライセンスの詳細は `sources.json` と、リポジトリ直下 `README.md` の「データ出典・ライセンス」を参照。
